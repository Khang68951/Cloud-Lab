Two directions of the same skill: **scaling up** when traffic grows, and **scaling down** when it is not needed.

## The scaling path from the AWS talk

1. One instance for everything.
2. Move the database to a managed service (RDS).
3. Add a load balancer, more instances, **more AZs**.
4. Take reads away: a **CDN** for static content, a **cache** for hot data, read replicas.
5. Auto Scaling; move suitable data to DynamoDB.
6. Split into services, add queues — and only then shard.

<Callout type="tip">
Don't skip steps. Take the next one only when the numbers show the previous one has become the bottleneck. The Lab shows you exactly that through utilisation and the Cost tab.
</Callout>
